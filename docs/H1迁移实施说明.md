## 3. H1 资产与机器人配置

### 3.1 新增独立机器人模块

新增 `src/blinkmimic/h1/__init__.py` 和 `h1_constants.py`。`get_robot("h1")` 通过原有动态加载接口读取该模块的 `SPEC`，训练入口使用 `--robot h1`。

### 3.2 关节顺序

```text
q_target = q_default + 0.25 × action
```

仿真存在编码器偏置时，沿用 BlinkMimic 环境已有的偏置处理。`armature=0.1`，关节被动阻尼 `viscous_damping=1.0`，软关节限位系数 `0.9`。PD 的 Kd 与被动阻尼分别设置。

## 4. 资产和动作如何进入目标仓库

新增 `tools/prepare_h1.py`，输入为参考仓库路径，输出默认是 BlinkMimic 的 `data/`：

```text
data/
├── h1_description/
│   ├── h1_training.xml
│   └── meshes/h1/             # 51 个网格文件
├── npz/h1/                    # 47 个动作，复制后的实际文件
└── h1_manifest.json           # 机器人、资产哈希、动作文件名、帧数与内容哈希
```

本次复制 1 个 XML、51 个网格和 47 个动作。动作合计 450794 帧，按 50 Hz 计约 2.504 小时。源目录中有相对软链接，准备工具会复制链接指向的文件内容，目标数据目录没有软链接。

准备前先检查源动作身份和数组；所有目标路径在写入前检查。已有同内容文件可重复使用，遇到不同内容的目标文件或清单会拒绝覆盖，需显式给出 `--overwrite`。

旧训练文档曾记录 43 个动作，而这次源目录实际有 47 个，含新增舞蹈切片。本次固定的是当前 47 个动作，不把旧的 43 动作成绩直接视为同一数据集结果。清单按内容哈希固定数据，之后往目录放文件不会自动改变该清单的训练集合。

`data/` 延续原仓库的忽略规则，不属于普通 Git 代码提交内容。将代码迁移到另一台机器时，需要同时复制这些数据，或在那台机器上运行准备工具。

### 4.1 H1 NPZ 加载器

`load_h1_npz()` 读取并检查：

- `robot` 必须为 `h1`，`asset_sha256` 必须匹配当前 H1 XML 和网格。
- `joint_names` 必须包含且仅包含 19 个 H1 关节，各出现一次。
- `body_names` 必须唯一且包含 `pelvis`。
- 帧率必须为 50 Hz，动作至少两帧，位置、关节角和四元数数组形状正确且数值有限。训练入口另外要求每段动作长于想象 horizon，避免采样不到合法起点。
- 四元数必须为单位四元数；格式直接使用源数据的 `wxyz`。

加载器通过名称定位 `pelvis`，并按名称把关节角重排到 XML 顺序。返回 `(根位置, 根四元数, 关节角, fps)`，从而适配 BlinkMimic 原有的 `MotionArrays` 接口。

`MotionLib` 对已经是 50 Hz 的数据直接读取，避免重复插值或浮点边界造成丢帧。其它帧率仍保留原来的重采样路径。根速度、关节速度和跟踪 body FK 由 BlinkMimic 自己计算；不依赖 SuperMimic 的 FK 实现或缓存。

### 4.2 清单与恢复训练

`MotionLib.from_dir()` 新增清单参数，检查机器人和资产身份、文件名是否合法及文件 SHA-256。H1 默认读取准备好的清单，`--motion_manifest` 可以指定另一份同格式清单。显式传入不同动作目录时，也可以使用目录内文件。

动作集合被记录为有序的文件名和内容哈希。恢复训练时核对这份身份，避免新增动作、替换同名文件或改变顺序后继续使用旧采样统计。

## 5. 物理根、跟踪锚点与策略观测

### 5.1 为什么区分 pelvis 和 torso_link

H1 的物理根仍是 `pelvis`。根状态、free joint 速度、根部高度与倾斜终止条件继续按 pelvis 定义。

为对齐参考仓库，跟踪锚点选择 `torso_link`。身体姿态奖励的重锚定、全局锚点奖励、Critic 相对误差和参考相对位姿反馈，都使用同一个躯干锚点，避免观测按 pelvis、奖励却按 torso 计算。

`Kinematics` 从机器人配置保存 `anchor_idx`；H1 的跟踪 body 共 12 个，首项仍是 pelvis，torso 是单独定位的锚点。通用 FK 原本已能处理 H1 的关节树，因此没有另写一套 H1 FK。

### 5.2 相对位姿反馈

共享 `MDP.relative_anchor()` 计算：

```text
relative_position = R_anchor_robotᵀ × (p_anchor_reference - p_anchor_robot)
relative_rotation = first_two_columns(R_anchor_robotᵀ × R_anchor_reference)
```

BlinkMimic 原来已有 6 维相对朝向；H1 将其定义到躯干锚点，并在观测末尾增加 3 维相对位置。没有把 SuperMimic 的 489 维目标向量直接复制过来。

H1 单帧观测顺序：

| 项目 | 维数 |
|---|---:|
| 相对默认位姿的关节角（含原有编码器偏置处理） | 19 |
| 关节速度 | 19 |
| 根部坐标系角速度 | 3 |
| 投影重力 | 3 |
| 上一动作 | 19 |
| 参考相对躯干朝向 | 6 |
| 参考相对躯干位置 | 3 |
| 合计 | 72 |

位置噪声半宽默认 `0.25 m`，原有其它噪声范围保留。观测维度、归一化向量、噪声向量、传感延迟分组，以及 `ObsPipeline.raw_obs()` 一并适配。仿真采集和想象 rollout 共享同一套相对锚点计算。

### 5.3 自动推导的尺寸

| 对象 | 当前 H1 尺寸或公式 |
|---|---|
| 受控关节 / 动作 | 19 |
| 状态存储 | `13 + 2×19 = 51` |
| 单帧观测 / 10 帧历史 | `72 / 720` |
| 每帧参考目标 | `15 + 2×19 = 53` |
| 默认 10 帧参考目标 | 530 |
| 默认随机化上下文 xi | `1 + 19 + 3 = 23` |
| 无动作延迟时 WM 输入 | `51 + 19 + 23 = 93` |
| WM 增量输出 | `12 + 2×19 = 50` |
| 默认 Critic 输入 | 668 |

网络依据这些接口构造，未在网络源码中把 G1 的维数替换为固定 H1 数字。G1 关闭位置反馈时仍使用原来的观测分支。

## 6. 奖励与朝向/手臂修复

`RewardCfg` 增加训练增强参数；H1 默认值由 `SPEC.training_rewards` 提供，也能用训练命令覆盖。

| 参数 | H1 默认值 | 实现用途 |
|---|---:|---|
| `w_arm_joint_pos` | 1.0 | 八个手臂关节分别计算指数跟踪得分后取平均 |
| `std_arm_joint_pos` | 0.5 | 手臂角度误差尺度，单位 rad |
| `w_arm_target_limit` | -0.2 | 惩罚策略请求的手臂目标角超出软限位 |
| `w_planar_drift` | -0.5 | 全局水平偏移的平滑代价 |
| `planar_drift_scale` | 1.0 | 水平位置尺度，单位 m |
| `w_heading` | 0.5 | 宽范围航向得分 |

主要公式：

```text
arm_score = mean(exp(-(q_arm - q_ref_arm)² / std²))
target_limit_cost = sum((relu(q_lo - q_target) + relu(q_target - q_hi))²)
planar_cost = sqrt(1 + ||p_anchor_xy - p_ref_anchor_xy||² / scale²) - 1
heading_score = (1 + cos(yaw_anchor - yaw_ref_anchor)) / 2
```

所有奖励继续乘控制步长 `0.02 s`。新增项使用 `training=True` 时启用，接入 `_reward_term()`，因此 Actor 通过世界模型想象轨迹也能获得这些项的梯度。

**固定评估奖励不加入这些增强项。** 仿真采样奖励、探测和评估仍使用基础六项跟踪奖励及原有惩罚，归一化上限仍为每步 `0.1`。这样日志中的基础训练回报和学习率触发阈值不会因新增正奖励而改变含义。`imag_rew` 包含训练增强，应与基础仿真回报分开解释。

## 7. 足底接触和镜像增强

### 7.1 足部元数据替代 G1 写死的名字

H1 使用 `left_ankle_link`、`right_ankle_link`，以及对应的 `*_ankle_link_collision`。训练和指标工具从配置读取足部索引，移除 G1 专属的名字和机器人判断。G1 配置显式补上原先两个 ankle-roll body，保留其旧接触定义。

H1 默认站姿中，踝关节原点约在地面上方 `6.90 cm`，足底则接近地面。把 G1 的 `4.5 cm` 踝关节阈值直接用于 H1 会误判接触。

### 7.2 可微的足底几何近似

每个 H1 足部碰撞网格有 4394 个编译顶点。为避免在想象训练的每一步变换全部顶点，加载时将网格坐标转换到 foot body 坐标系，提取轴对齐包围盒的 8 个角点。

`foot_kinematics()` 用 FK 变换角点，取最低角点高度，同时计算该点的速度：

```text
p_point = p_foot + R_foot × point_local
v_point = v_foot + w_foot × (R_foot × point_local)
```

H1 接触阈值是足底代理高度低于 `0.015 m`，穿地基准为零。训练接触项使用 sigmoid 平滑高度指标。参考接触修复仍使用每个动作的 5% 高度分位数，加 1.5cm 裕量并限制水平速度；指标和训练使用一致的几何路径。

这是一种足部包围盒代理，不是直接读取物理接触力，也不是精确网格穿透深度。原始参考动作的根高度、世界轨迹和四元数没有被逐帧贴地或旋转修改。

摩擦随机化只作用于 H1 足部碰撞几何。随机化的时间安排保留 BlinkMimic 现有实现：默认摩擦每环境初始化一次，编码器偏置每回合采样，COM 在初始化时采样。

### 7.3 H1 腰部镜像

原 `Mirror` 依据名称里的 `roll/yaw` 翻转符号，会漏掉实际绕 Z 轴旋转的 `torso_joint`。H1 提供显式的“对应关节、符号”表，torso 符号为 `-1`，左右 yaw/roll 也翻转符号，其它对应关节保持正号。

镜像构造时检查对应关系是 involution，即执行两次恢复原关节。回归验证还覆盖状态、xi、body 位置、旋转和速度的镜像 FK 关系。

## 9. 检查点身份与恢复

新增 `checkpoint.py`：

- 资产身份：XML 字节与所有网格的相对名称、内容 SHA-256。
- 控制/观测身份：关节和 body 名、root/anchor 定义、位置反馈开关、默认关节角、动作缩放、PD/力矩/惯量/阻尼/延迟参数、传感配置和足部定义。
- 动作身份：有序的动作文件名和内容哈希。

普通检查点、轻量策略检查点和完整 `last.pt` 都保存机器人与动作身份。训练恢复、单检查点评估、批量评估、精度指标和 ONNX 导出均校验身份。H1 不接受缺少该元数据的旧检查点，也不接受 G1 或 SuperMimic 权重。

原有 G1 检查点没有新增身份时保留兼容分支。恢复训练还要求动作文件内容一致，并检查结构化 WM、参考动作跳连、历史/目标帧数、网络宽度和优化器类型。更换这些定义时，应新建训练，不能仅因为动作都是 19 维就直接恢复。

`--resume` 保留原实现的 warm restart 语义：恢复网络、优化器、EMA、学习率触发状态及采样统计；经验池、仿真状态和随机数流不保存，所以不是逐步完全确定性的续跑。

## 10. 评估、视频和 ONNX 的同步修改

### 10.1 评估入口

单检查点评估、批量评估和精度指标增加动作清单支持及检查点身份校验。单检查点评估也支持设备参数和自动创建轨迹输出目录。

指标工具增加根部水平位置误差、航向误差和按关节名称输出的角度误差。奖励中的全局锚点是 torso；名为 root 的评估指标明确使用物理根 pelvis 的世界位置和朝向，避免将两者混淆。接触、滑移和穿地指标使用同一足部几何定义。

同时修复跨机器人随机化转移在源机器人没有 PD 增益随机化组时对空列表调用 `max()` 的问题。

### 10.2 视频

H1 默认在世界坐标中显示参考重影，以便直接观察轨迹漂移；`--local_ghost` 可以用于局部姿态检查。参考模型使用独立蓝色透明材质，避免继承 H1 的黑色材质。

渲染工具优先使用 `FFMPEG_BINARY` 或系统 ffmpeg，缺失时回退到 `imageio_ffmpeg`；若二者都没有，给出安装方式。输出目录自动创建，正常结束时关闭 Renderer 并检查编码器退出码。

### 10.3 ONNX

导出按机器人配置计算观测维数，H1 输入为 `(1, history, 72)`。`PolicyWithMotion` 按实际 `anchor_idx` 输出下一帧躯干参考姿态，不再假定跟踪 body 第 0 项就是奖励锚点。

H1 增加第九个输出 `next_anchor_pos_w`；原有 `next_anchor_quat_w` 也指向 torso。元数据记录观测顺序、维数、root/anchor 名称、控制参数和机器人身份。G1 不启用位置反馈时仍保留原来的八个输出。

`play_onnx.py` 通过 MuJoCo CPU FK 从根姿态和关节角构造躯干位姿，再与 ONNX 的参考锚点输出形成相对反馈。这条路径独立于 MDP 的观测拼接。当前训练使用仿真位置；真正部署到机器人时需提供对应的位置估计。
